## §0 三问法定位验证

> 定位任何产品前必须回答的三个问题。

### Q1：**用户是谁？**（WHO）

| 用户画像 | 描述 | 占比 |
|----------|------|------|
| iOS 深度用户 | 追求个性化铃声，讨厌默认、找不到好听的自定义铃声，愿意为工具付费 | 45% |
| 音乐爱好者 / 发烧友 | 自己听的歌想截最爽那段当铃声，追求切点专业度（不刺耳、循环丝滑） | 25% |
| 短视频创作者 | 需要批量生产铃声素材，追求「动态数量」「质量稳定」「命名规范」 | 15% |
| 怀旧党 / ACG 粉 | 经典老歌、OP/ED 想做铃声，手动截了 20 次还没好 | 10% |
| 设计师 / 极客 | 喜欢酷炫 UI、工具型产品，享受「把复杂变精致」的体验 | 5% |

**核心用户群（ICP）**：25–40 岁 iOS 用户，拥有 ≥100 首歌的个人曲库，**曾尝试手动用 GarageBand/Audacity 剪铃声但放弃**，愿意用「拖一首歌 → 自动出候选 → 一键导出」的工具。

### Q2：**解决什么问题？**（WHAT PAIN）

| # | 痛点 | 现有方案的缺陷 | RingtoneMaster 的解法 |
|---|------|---------------|----------------------|
| P1 | **切点不准**：手动剪要么开头炸要么结尾哑，循环接缝爆音 | GarageBand/Audacity 需对齐波形到 sample，无音乐结构意识 | Agent 识别 downbeat/anchor 自动切点 + 循环接缝评分 |
| P2 | **数量盲区**：一首歌只能手动剪 1–2 段，好片段可能浪费 | 单一切点逻辑，无候选池 | 动态枚举 N 个候选（根据音频复杂度），评分排序 |
| P3 | **质量焦虑**：怕导出后响度不够、TP 超标、循环刺耳 | 无 QA 环节，iPhone 可能拒审或听感差 | 内置 LUFS/TP/时长/循环 4 维 QA，PASS/FAIL 可视化 |
| P4 | **导出繁琐**：要转 m4r、要同步到 iPhone、要命名 | 多工具协作 + 手动 Finder 拖拽 | 一键生成 m4a+m4r + iPhone 复制指引 + 可配置命名规则 |
| P5 | **体验割裂**：要么命令行工具，要么土味网页工具 | 工具感 > 产品感，用完就删 | 深空暗色 + 玻璃拟态 + 波形可视化，像专业音频仪器 |

**一句话价值主张**：**拖入一首歌，自动分析出 5–20 个专业级候选铃声，可视化评分 + 循环接缝预览 + 一键导出 m4r，比手动剪快 10×，比其他 AI 准 3×。**

### Q3：**为什么是现在？**（WHY NOW）

| 趋势 | 时机判断 |
|------|---------|
| **本地大模型成熟** | wav2vec2/whisper 等语音分析模型本地可跑（M 系列 Mac 10s 分析 3min 音频），无需云 API |
| **iPhone 用户基数** | 全球 ≥15 亿 iOS 活跃设备，个性化需求持续增长（iOS 17+ 铃声设置 UI 反而变复杂了） |
| **AI 工具用户习惯养成** | 2024–2026 年间，用户对「AI 帮我做 xxx」的接受度从 30% 提升到 70%+，音频 AI 赛道爆发 |
| **隐私觉醒** | 用户不愿上传私人曲库到云端工具，本地分析成为刚需卖点 |
| **跨端框架成熟** | Next.js + Taro + Capacitor 组合，一套代码覆盖 Web/H5/小程序/APP 的成本降低 80% |

**结论**：三问法全部通过 ✅。用户清晰、痛点真实、时机成熟。

## §1 产品愿景与设计原则

### 1.1 愿景
> 打开即懂：拖入音频 → 看着它被理解 → 听见候选 → 一键导出。整个过程像在操作一台精致的音频仪器，而不是填表单。

### 1.2 设计原则（8 条）
1. **一屏一事**：每个阶段只突出一个主任务，避免信息过载
2. **听见即所得**：所有候选可即时试听，波形与切点可视化
3. **克制的酷**：暗色 + 霓虹只用于强调和状态，不堆砌特效
4. **专业可信**：评分、QA、时间码、参数全部可见可追溯
5. **丝滑优先**：动效服务于理解，时长 120–320ms，缓动统一 `cubic-bezier(.22,1,.36,1)`
6. **零学习成本**：默认路径 3 步完成；高级参数折叠但可达
7. **失败也优雅**：空状态、错误、降级都有清晰引导
8. **全链路一致性**：所有设计、逻辑、程序、UI、布局、元素、界面在同一项目或完整工作流中必须保持。为什么要这样？——因为人的大脑和手指在跨端跨尺寸的操作中，依赖可预测性来降低认知负荷。
   - **因果链一致**：操作 → 状态 → 反馈的前因后果可追溯，不存在「点了但没反应」「改了但没生效」的断链
   - **数据一致**：同一字段在不同页面显示相同值；store 单一数据源；刷新/跳转/重进页面不丢失状态
   - **操作一致**：播放按钮永远是 ▶ / ⏸ 且行为相同；参数调节永远有 toast/visual 反馈；相同语义用相同组件
   - **视觉一致**：相同类型信息用相同字号/色值/间距；icon 风格统一；颜色只承载状态（成功绿、错误红、强调青）
   - **跳转一致**：有导航入口必有可达路由；死链视为 P0 Bug；返回按钮总回到上一个上下文
   - **跨端一致**：同一条创作路径（拖入 → 候选 → 编辑 → 导出）在桌面 / 平板 / 手机上保持相同的信息架构和决策顺序
   - **跨尺寸一致**：小屏折叠不等于隐藏功能，而是压缩信息密度；关键操作（播放、确认、导出）永远不超过拇指热区的边界

#### 1.2.1 一致性的底层理论依据（人体工学 + 多端适配）

> 一致性不是审美偏好，是让人体在 0.3 秒内完成决策的工程前提。

**认知负荷模型**：大脑处理每一条信息都消耗工作记忆。当同一语义用了不同 icon（比如 A 页播放按钮是三角形，B 页是圆形），用户的前额叶必须先识别"这也是播放按钮"再执行操作——这比直接点击多了 200–400ms 的决策时延。连续做 10 次，就是 2–4 秒的无意义等待，而用户的耐心阈值是 **3 秒**。

**视觉流连续性**：人眼扫视轨迹遵循 F 型和 Z 型。桌面 27" 屏上波形在左侧、参数在右侧；到了 iPhone SE 的 4.7" 窄屏，波形被挤到顶部、参数堆在下方——视觉流被打断，用户需要"重新学习"一页的阅读顺序。一致性原则要求：**关键信息块的相对位置优先级不变**，只是自适应布局方向（水平 → 垂直），而不是换一套排版逻辑。

**触控热区（拇指可达性）**：手指触控精度远低于鼠标。iPhone 上，拇指的舒适操作区是屏幕下 1/3 的扇形区域（人体工学数据：4–6cm 半径）。一致性原则要求：导出、播放、确认等高频动作永远落在这个区域。桌面端对应为**视线热区**（屏幕中央 ±20°），同一语义的按钮在两端都占据各自平台的"优先操作位"。

**跨端肌肉记忆**：用户在 Mac 上熟练操作后，拿起 iPad 继续同一个项目。如果 Mac 上播放候选是"点击候选卡片 → 自动播放"，而 iPad 上变成"点击卡片 → 再点一个隐藏的播放图标"，肌肉记忆就被打破——这个断点会让用户产生"这个 App 我好像没见过"的陌生感。一致性原则要求：**核心交互范式跨端不变，只改变信息密度和布局方向**。

**状态持久化的心理锚点**：用户中途切走做别的事（接电话、发消息），回来时不应该"从记忆里重建项目状态"。store 持久化就是让页面回到离开时的样子，给用户一个"我一直在这儿"的心理锚点。如果刷新后当前项目丢了，用户会怀疑自己刚才的操作有没有真的保存——这是因果链断了，不是功能 Bug。

#### 1.2.2 最终目标：易操作（Operability）

所有一致性原则收敛到一个可量化的指标——**完成一次完整创作流程（拖入 → 选候选 → 编辑 → 导出）的耗时和决策次数**。

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| 端到端耗时（桌面） | ≤ 45 秒 | 从拖入文件到下载按钮出现 |
| 端到端耗时（移动） | ≤ 60 秒 | 同上 |
| 决策次数 | ≤ 8 次 | 需要用户主动判断/选择的节点数 |
| 失败/重试次数 | 0 次 | 因操作混淆、数据丢失、死链导致的回退 |
| 认知确认次数 | 0 次 | 「我刚才点对了吗？」「这个值保存了吗？」 |

### 2.4 跨尺寸一致性断点规则

> **核心约束**：从 360px 到 2560px，信息架构不变，只改变密度和方向。每个断点只在必要时折叠次要信息，**核心操作和视觉优先级永远不降**。

| 断点（CSS 宽度） | 布局变化 | 什么不变 | 什么折叠/移位 | 人体工学依据 |
|-----------------|---------|---------|-------------|-------------|
| **≥1440px**（桌面宽屏） | 三栏：波形（主）+ 参数 + QA | 波形始终左侧 60%+ 宽度 | QA 雷达图常显 | 视线热区中央 ±20°，波形必须占住 |
| **1024–1439px**（笔记本） | 两栏：波形 + 右侧抽屉 | 波形始终左侧主导 | QA 雷达图折叠为抽屉 Tab | 视线距离缩短，右侧 30° 内仍可达 |
| **768–1023px**（平板/横屏） | 两栏：波形 + 底部抽屉 | 播放/导出按钮位置 | 参数面板收到底部抽屉 | 平板握持时拇指热区在下 1/3 |
| **360–767px**（手机） | 单栏垂直：波形→候选→编辑→导出 | 播放按钮永远在底部 Tab 区 | 参数/QA 全部 Tab 化 | 拇指扇形热区仅覆盖下 1/3 屏，顶部触需换手 |
| **<360px**（超窄屏） | 单栏 + 大字号（14→16） | 播放/导出按钮尺寸≥48×48px | 次要信息（评分明细）折叠 | 触控精度极限 7mm，按钮不可再小 |

**跨端一致性红线（禁止）**：
- ❌ 桌面播放按钮在左、移动变到右
- ❌ 桌面候选卡片点击自动播放、移动需要多一步才播放
- ❌ 桌面波形可拖动选区、移动版本没有这个能力
- ❌ 某端刷新丢失项目、某端不丢——必须全端持久化策略一致

**拇指热区与视线热区的动作映射**：

| 操作类型 | 桌面（视线热区） | 移动（拇指热区） | 一致性实现 |
|---------|----------------|----------------|----------|
| 播放/暂停 | 波形左侧固定位置 | 底部 Tab 区固定位置 | 同组件 `PlayButton`，位置由断点决定 |
| 导出 | 右上或右下固定位置 | 右下固定（FAB） | 同组件 `ExportButton`，始终锚定视口角 |
| 确认/保存 | 当前卡片右侧 | 键盘上方或底部 | 同语义 icon + 同色值（强调青） |
| 取消/返回 | 左箭头或 ESC | 系统返回手势 | 同语义 icon，系统手势是额外通道 |

```
                                 │ 5. 导出+报告 │
                                 └──────────────┘
```

### 3.3 关键业务规则

| # | 规则 | 说明 |
|---|------|------|
| BR1 | 成品时长 ≤ 29.99s | iPhone 硬性要求 |
| BR2 | 候选数量动态 5–20 | 根据音频复杂度自动调整 |
| BR3 | 质量门禁 | 不满足 LUFS/TP/时长/循环 QA 不可导出 |
| BR4 | 循环接缝必须评分 ≥ 70 | 否则标红提示 |
| BR5 | 命名模板可配置 | `{name}_ringtone_{index}_{start}-{end}` |
| BR6 | 同时生成 m4a + m4r | iPhone 需要 m4r |
| BR7 | 设置即时保存 | 本地持久化，无需"保存"按钮 |

### 3.4 输入格式支持

| 类别 | 支持格式 | 处理方式 | 备注 |
|------|---------|---------|------|
| **音频** | MP3 / M4A / WAV / FLAC / AAC / OGG / Opus / WMA / AIFF / ALAC | 直接解码进入分析管线 | 浏览器 Web Audio API 原生支持 |
| **视频** | MP4 / MOV / MKV / AVI / WMV / FLV / WebM / M4V / MPG / TS / 3GP 等 | **ffmpeg.wasm 浏览器端抽取音轨** → WAV 44.1kHz → 进入分析管线 | 所有视频格式一视同仁，自动检测音轨 |

**视频抽音轨流程**（纯浏览器端，无上传）：
```
用户拖入视频 → detectSourceKind() 识别扩展名/MIME → 
  ├─ audio → 直接走 Web Audio API
  └─ video → ffmpeg.load() 懒加载 → ffmpeg.writeFile() 写入 →
              ffmpeg.exec(["-i", in, "-vn", "-acodec", pcm_s16le, "-ar", "44100", "-ac", "2", out.wav"]) →
              readFile() → Blob → URL.createObjectURL → 走 Web Audio API
```
- 懒加载：首次遇到视频才下载 ffmpeg-core.js / wasm（~25MB），后续复用单例
- 进度回传：onProgress(5→15→25→85→100)，配合 UI 进度条
- 安全：全程本地处理，视频字节不出浏览器
